04

Writing voice

Warm, plain, and first-person, the way Erin-Marie actually talks. Like explaining something to a friend. Never salesy, never "tech bro."

Do

  • Write in plain, everyday words and short sentences.
  • Use first person and contractions (I, we, didn't, it's).
  • Say things the way you'd say them out loud ("the catch was…", "it turned out to be one of the handiest parts").
  • Be warm and human; a little enthusiasm is good.
  • Keep only what's true; describe what the app actually does.

Don't

  • No tech-bro / buzzword language: north star, leverage, seamless, robust, supercharge, game-changer, unlock, "it's the next thing," level up.
  • No product/design jargon in prose: spec, wireframe, mobile-first, graceful fallback, placeholder, stand-in, reads distinctly, limitation.
  • No em dashes (—). Use commas, colons, or periods.
  • Don't repeat "the" in a list: write "the idea, names, photos and design direction," not "the idea, the names, the photos…"
  • Don't overstate; if something isn't built yet, say so plainly.
A few before → after
  • ✗ "That became the north star for how the tree should feel."
    ✓ (cut it, or "That's the feeling I was going for.")
  • ✗ "It had one real limitation: it was built for desktop… the next version needed to be mobile, first."
    ✓ "The catch was that it only really worked on a computer… so the next version had to work well on a phone."
  • ✗ "No spec, no wireframe. Just the intent, typed in plain language."
    ✓ "No plan, no drawings. I just typed what I wanted, in plain words."
  • ✗ "Rebuilt with a mobile-first static site; names in a Cloudflare Pages secret."
    ✓ "I rebuilt it as a mobile web app. A developer helped add a secret password and keep the names safe in a database."
Small conventions
  • Write RSVP in caps (it's an acronym).
  • Sign off warm and short ("That's a wrap, thanks for reading!").
  • Prefer active voice ("I added…", "Claude suggested…").
05

Imagery & privacy

Photos and screenshots carry the warmth; treat family details with care.

  • Real family last names are hidden on the interior design images (the person-card and wireframe shots). Keep that consistent if you add more.
  • The Driscmas app itself is private and password-protected; never link to the live app or publish the password.
  • Images: rounded corners (16–18px), hairline border, soft shadow. Cap width to the image's native size so it stays crisp; don't upscale.
  • Captions are short and in the serif italic voice.
06

Where it lives

  • erin-marie.com is a static site on GitHub Pages (repo: erin-marie-site).
  • New pages are plain HTML that reuse the tokens above (copy the :root variables and shared component classes).
  • Clean URLs: a file like driscmas.html is served at /driscmas, no extension needed.
  • To publish: commit in GitHub Desktop, push, and the site rebuilds in a minute or two.
